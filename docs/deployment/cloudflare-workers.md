# Cloudflare Workers

Air can run in Cloudflare Python Workers through Cloudflare's ASGI adapter.
This guide documents the packaging and runtime versions validated against
Pyodide 0.28.3.

## Python runtime and dependencies

Configure the Worker application for Cloudflare's stable Python 3.13 runtime
and add the packaging/runtime tooling to the development dependency group:

```toml
[project]
requires-python = ">=3.13,<3.14"
dependencies = [
    "air",
    # Wheels available in Pyodide 0.28.3 for compatibility date 2026-07-27.
    "markupsafe==3.0.2",
    "pydantic==2.10.6",
    "pydantic-core==2.27.2",
]

[dependency-groups]
dev = [
    "workers-py==1.16.0",
    "workers-runtime-sdk==1.6.3",
]
```

Air itself supports Python 3.13 and 3.14. The Worker application intentionally
uses `>=3.13,<3.14` because compatibility date 2026-07-27 selects Cloudflare's
stable Python 3.13.2 / Pyodide 0.28.3 runtime. Compatibility dates before
2025-09-29 select Python 3.12 and cannot install Air; update an older Worker to
the compatibility date shown below or another date on or after 2025-09-29.
Python 3.14 Workers require experimental flags and are outside the configuration
validated by this guide. These constraints belong in the downstream Worker
application and do not narrow Air's supported Python range.

Commit both `uv.lock` and the `pylock.toml` generated by pywrangler. These
downstream pins match Cloudflare's Pyodide 0.28.3 package index. Unconstrained
resolution can select MarkupSafe or Pydantic packages without compatible
Pyodide wheels and then attempt native or Rust builds. Re-resolve and verify the
pins when changing the Worker compatibility date; do not add them as universal
Air constraints for native installations.

## Worker entry point

Save the Worker entry point as `src/worker.py`. Cloudflare's ASGI adapter
connects a `WorkerEntrypoint` to the Air app:

```python
import asgi
from workers import WorkerEntrypoint

from main import app


class Default(WorkerEntrypoint):
    async def fetch(self, request):
        return await asgi.fetch(app, request, self.env)
```

The corresponding Wrangler settings are:

```toml
name = "air-worker"
main = "src/worker.py"
compatibility_date = "2026-07-27"
compatibility_flags = ["python_workers"]
```

Use Wrangler 4.114.0, for example with
`npm install --save-dev wrangler@4.114.0`.

## Sync, development, and deployment

With workers-py 1.16.0, the current commands are:

```sh
uv sync
uv run pywrangler sync --force --upgrade
uv run pywrangler dev
uv run pywrangler deploy
```

For a packaging-only deployment check, use:

```sh
uv run pywrangler deploy --dry-run
```

## Error-path smoke check

In addition to the application's `GET /` route, expose validation routes that
explicitly raise a 404 and an unhandled exception:

```python
@app.get("/http-404")
async def http_404() -> None:
    raise air.HTTPException(status_code=404)


@app.get("/error")
async def error() -> None:
    raise RuntimeError("smoke-test error")
```

Copy Air's smoke checker into the downstream project:

```sh
mkdir -p scripts
curl -fsSL \
  https://raw.githubusercontent.com/feldroy/air/main/scripts/check_worker_smoke.py \
  -o scripts/check_worker_smoke.py
```

While `pywrangler dev` is running, use it to check the homepage, an unknown
route, the explicit 404, and Air's 500 response:

```sh
uv run python scripts/check_worker_smoke.py http://127.0.0.1:8787
```

The checker requires `200`, `404`, `404`, and `500` respectively and verifies
that the error responses contain Air's normal error pages.

## Validated configuration

Air was validated with workers-py/pywrangler 1.16.0,
workers-runtime-sdk 1.6.3, Wrangler 4.114.0, and compatibility date 2026-07-27.
A clean pywrangler sync resolved MarkupSafe 3.0.2, Pydantic 2.10.6, and
pydantic-core 2.27.2 from the Pyodide 0.28.3 package index.

Local workerd returned:

- `GET /` → 200
- `GET /missing` → Air 404
- `GET /http-404` → Air 404
- `GET /error` → Air 500

The error-path validation application described above contains 536 modules and
is 9,700.23 KiB raw / 2,409.74 KiB gzip. The exception-handler change adds
1.85 KiB raw / 0.65 KiB gzip. For comparison, the minimal Worker validation
contains 525 modules and is 9,448.39 KiB raw / 2,352.48 KiB gzip. Both remain
below the 3 MiB compressed upload limit.
